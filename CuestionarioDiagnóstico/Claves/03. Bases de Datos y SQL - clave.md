# 03. Bases de Datos y SQL — Clave

Consulta esta clave después de responder el módulo completo.

## Nivel 1 — Esencial

### BDD-E1 — B

**Evalúa:** Función de una clave primaria.

**Explicación:** La clave primaria distingue cada fila mediante un valor, o combinación de valores, que no se repite.

### BDD-E2 — A

**Evalúa:** Integridad referencial.

**Explicación:** La clave foránea expresa la relación y permite exigir que el cliente referenciado exista.

### BDD-E3 — C

**Evalúa:** Filtrado básico en SQL.

**Explicación:** `WHERE` establece la condición que deben cumplir las filas antes de formar el resultado.

### BDD-E4 — C

**Evalúa:** Propósito básico de la normalización.

**Explicación:** Separar datos que representan entidades distintas reduce duplicación y evita actualizar una misma información en muchos lugares.

### BDD-E5 — B

**Evalúa:** Propiedades de las transacciones.

**Explicación:** La atomicidad trata las operaciones de una transacción como una unidad: se confirman todas o se revierten todas.

## Nivel 2 — Aplicado

### BDD-A1 — C

**Evalúa:** Uso razonado de índices.

**Explicación:** Un índice sobre una columna consultada puede evitar recorridos completos, aunque su beneficio debe medirse porque también tiene costo.

### BDD-A2 — A

**Evalúa:** Uso de transacciones para cambios relacionados.

**Explicación:** El descuento y el abono forman una sola operación lógica; si uno falla, la transacción debe deshacer ambos cambios.

### BDD-A3 — B

**Evalúa:** Selección de tipos de unión.

**Explicación:** Un `LEFT JOIN` conserva todas las filas del lado izquierdo y agrega las coincidencias del lado derecho cuando existen.

### BDD-A4 — A

**Evalúa:** Prevención de inyección SQL.

**Explicación:** Los parámetros mantienen los datos separados de la estructura de la consulta y evitan que la entrada sea interpretada como SQL.

### BDD-A5 — C

**Evalúa:** Protección de invariantes de datos.

**Explicación:** Una restricción en la base protege la regla sin importar qué aplicación o proceso intente escribir el precio.

## Nivel 3 — Profundización

### BDD-P1 — B

**Evalúa:** Diagnóstico de rendimiento de consultas.

**Explicación:** El plan y las mediciones muestran cómo se accede a los datos y dónde se concentra el trabajo real.

### BDD-P2 — A

**Evalúa:** Consistencia ante operaciones concurrentes.

**Explicación:** Una transacción con bloqueo, aislamiento u otra verificación atómica adecuada impide confirmar dos ventas sobre la misma unidad.

### BDD-P3 — A

**Evalúa:** Evolución compatible de esquemas.

**Explicación:** El cambio aditivo permite que clientes antiguos y nuevos convivan mientras los datos y consumidores se migran de forma gradual.

### BDD-P4 — C

**Evalúa:** Compensación entre normalización y rendimiento.

**Explicación:** La duplicación puede mejorar una lectura crítica, pero exige una estrategia clara para mantener consistente el dato derivado.

### BDD-P5 — B

**Evalúa:** Validación de recuperación ante fallos.

**Explicación:** Solo una restauración probada demuestra que el respaldo es utilizable y que cumple los objetivos de tiempo y pérdida de datos.
