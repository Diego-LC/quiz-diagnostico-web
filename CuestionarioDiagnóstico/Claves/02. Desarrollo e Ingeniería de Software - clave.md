# 02. Desarrollo e Ingeniería de Software — Clave

Consulta esta clave después de responder el módulo completo.

## Nivel 1 — Esencial

### ISW-E1 — B

**Evalúa:** Formulación de requisitos verificables.

**Explicación:** Un porcentaje y un tiempo definidos permiten medir objetivamente si el requisito se cumple.

### ISW-E2 — A

**Evalúa:** Propósito del control de versiones.

**Explicación:** El control de versiones conserva el historial y permite comparar, combinar o recuperar cambios, pero no garantiza su calidad.

### ISW-E3 — C

**Evalúa:** Diferencia entre niveles de prueba.

**Explicación:** Una prueba unitaria se concentra en una pieza pequeña de lógica y limita las dependencias externas para dar retroalimentación rápida.

### ISW-E4 — B

**Evalúa:** Separación de responsabilidades.

**Explicación:** Componentes con responsabilidades claras son más fáciles de entender, cambiar y probar de manera independiente.

### ISW-E5 — C

**Evalúa:** Concepto de contrato de software.

**Explicación:** El contrato expresa lo que un consumidor puede enviar, recibir y observar sin imponer la implementación interna.

## Nivel 2 — Aplicado

### ISW-A1 — C

**Evalúa:** Refinamiento de requisitos ambiguos.

**Explicación:** Antes de escoger una solución, el equipo debe convertir términos vagos en resultados observables y criterios de aceptación medibles.

### ISW-A2 — B

**Evalúa:** Selección de pruebas para límites de integración.

**Explicación:** Las pruebas de contrato o integración comprueban que emisor y receptor coincidan en el formato y significado intercambiado.

### ISW-A3 — A

**Evalúa:** Refactorización segura de código heredado.

**Explicación:** Las pruebas de caracterización hacen visible el comportamiento existente y protegen contra cambios accidentales durante pasos pequeños.

### ISW-A4 — A

**Evalúa:** Trazabilidad y tamaño de los cambios.

**Explicación:** Cambios enfocados permiten revisar su intención y revertir una modificación riesgosa sin retirar trabajo no relacionado.

### ISW-A5 — C

**Evalúa:** Optimización guiada por evidencia.

**Explicación:** Se debe investigar el componente que domina la latencia y luego medir nuevamente para confirmar el efecto real.

## Nivel 3 — Profundización

### ISW-P1 — B

**Evalúa:** Compatibilidad semántica de contratos.

**Explicación:** Un consumidor depende también del significado observable; conservar el esquema no evita una ruptura si ese significado cambia.

### ISW-P2 — C

**Evalúa:** Integración gradual de funcionalidades.

**Explicación:** Los incrementos pequeños reducen conflictos y permiten revisión temprana; la bandera mantiene oculto el comportamiento incompleto.

### ISW-P3 — A

**Evalúa:** Diseño de efectos ante entrega repetida.

**Explicación:** Registrar la operación y hacer idempotentes sus efectos permite reconocer un mensaje repetido sin ejecutar nuevamente cada consecuencia.

### ISW-P4 — B

**Evalúa:** Elección entre abstracción y variación explícita.

**Explicación:** Componer políticas conserva lo verdaderamente común sin crear una clase rígida llena de combinaciones de banderas.

### ISW-P5 — A

**Evalúa:** Integración continua y entrega progresiva.

**Explicación:** Los cambios pequeños facilitan revisión e integración. La bandera mantiene oculto el comportamiento hasta que exista evidencia suficiente para activarlo.
